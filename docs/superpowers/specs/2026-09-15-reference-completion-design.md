# DO:NUTS 누락 기능 완성 설계

사용자는 2026-09-15 비교 보고서의 누락 항목을 현재 웹 디자인에 맞게 구현하고 불필요한 기능 설명 문구를 제거하도록 요청했다. 이미 확정된 정책과 조사 결과를 설계 기준으로 사용한다. 별도 승인 질문 없이 진행하라는 사용자 지침을 적용한다.

## 화면과 문구

- 기존 `bg-bg`, `text-ink`, `text-gold`, `border-border`, `rounded-card`와 현재 글꼴을 유지한다. 새 색상·브랜드·장식 효과를 만들지 않는다.
- 회원 홈은 작은 회원 프로필 → 현재 클래스/다음 회차 → 오늘의 학습과 XP → 참가 가능한 모임 → 파트너 순으로 구성한다. 종료 클래스는 기록에서 구분한다.
- CLASS는 복수 소속 선택을 유지하면서 회차 진행도·제목·설명·상세를 제공한다.
- CLUB은 내 클럽 정보와 참가 가능한 모임을 함께 보여주고, 소속 신청은 별도 구역으로 유지한다.
- CLASS / CLUB / HOME / PARTNERS / MY 메뉴를 복원한다. 리더 진입은 서버에서 실제 권한을 조회하고, 관리 모드에서도 회원으로 돌아갈 수 있게 한다.
- 버튼이나 제목을 다시 설명하는 문장, 구현 방식·서버 채점·검수 절차·권한 구조에 대한 장황한 문구를 제거한다. 신청 자격·대기 기한·파괴적 동작 결과·오류와 비어 있는 상태에서 필요한 안내는 간결하게 남긴다.

## 독립 도메인

1. 파트너: 회원 목록·홈 미리보기, 관리자 생성/수정/삭제/정렬, 기존 Supabase Storage 업로드 재사용. RLS와 관리자 서버 검증. 신규 마이그레이션 0032.
2. 클래스/클럽: 회차 제목·설명 저장과 회원 상세, 진행도, 기본명 제안, 리더 검색, 클럽 로고 업로드/노출·회원 수. 신규 마이그레이션 0033. 기존 날짜/출석 상태 전이를 유지한다.
3. 학습/XP: 구조화된 포커 스팟과 버전 보존, 5문항 단계별 답변과 전체 제출 후 채점, 완료/복습, 학습 XP를 포함한 이력·주간 XP. 기존 최초 제출·검수·공통 일일 세트를 유지한다. 신규 마이그레이션 0034.
4. 회원/모임: 프로필 수정·종합 조회·필터·지원용 비밀번호 복구·탈퇴 익명화, DONUTS 주최 모임, HOT 우선·참여 상태·인원·확인 동작. 신규 마이그레이션 0035. 기존 도메인 잠금과 이력 보존을 유지한다.

## 데이터와 운영

- 적용된 마이그레이션은 수정하지 않는다. 0032–0035는 기존 데이터와 호환되도록 추가한다.
- 탈퇴는 재시도 가능한 단계로 관리한다. 먼저 DB에서 접근과 권한을 차단하고 개인정보 및 식별 가능한 스냅샷을 익명화한다. Auth 식별자는 기록의 외래키 보존을 위해 삭제하지 않고 로그인 불가한 익명 계정으로 처리한다. 진행 상태를 기록하고 Auth 정리 실패를 완료로 표시하지 않는다.
- 이메일 실제 발송 인프라는 기존 사용자 보류를 유지한다. 관리자 비밀번호 지원은 기존 Supabase 복구 기능으로 연결하고, 실제 회원에게 테스트 메일을 보내지 않는다.
- 가입은 기존 설정과 실제 안내 문서를 검토한다. 개인정보 처리 사실과 운영 연락처를 확인하여 동의/안내를 연결한다. 임의 회사 정보나 가짜 URL을 만들지 않는다.
- 파트너·문항·회원 운영 데이터를 가짜로 채우지 않는다. 기존 승인된 테스트 계정 및 로컬 격리 DB로 입력·변경·권한을 검증한다.
- 기존 승인된 Supabase/Vercel 환경을 사용한다. 생산 DB 백업과 마이그레이션 검증 후 기존 배포 경로로 반영한다.

## 검증

폼·단계 전환·정렬·권한·탈퇴 재시도·PII 제거·XP 합계를 대상으로 의미 있는 자동 검증을 추가한다. 문구 제거와 단순 배치 변경에 구현을 복제하는 테스트를 쓰지 않는다. 타입 검사, 테스트, 린트, 빌드, 격리 PostgreSQL, 실제 브라우저의 모바일·태블릿·데스크톱·접근성 검사 및 승인된 테스트 계정으로 주요 동작을 확인한다.
