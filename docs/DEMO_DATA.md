# DO:NUTS 기능 테스트 데이터

모든 데이터는 `[TEST]` 표시가 있는 기능 확인용 예시입니다. 실제 운영 일정, 실사용 회원, 정식 문항 검수 기록이 아닙니다.

## 범위

| 영역 | 준비한 데이터 |
|---|---|
| 계정 | 클래스장, 클럽장, 일반회원, 대기회원, 신청회원, 기록회원 6개 |
| 학교 | 테스트 학교 2개 |
| 클래스 | 출석 운영반, 복수 소속반, 종료반, 후속 안내반, 자동 소속 실행 대기반 |
| 회차 | 11회차: 완료·잠금, 진행 중·미확인 출석, 향후 일정 |
| 클럽 | 학교가 다른 회원의 가입과 복수 소속을 포함한 2개 |
| 모임 | 신청 가능, 만석, 자리 확정 대기, 만료 이력, 게스트·무제한, 최근 완료, 24시간 경과, 취소 |
| 학습 | 문항 7개·버전 8개: 검수 완료 5개, 초안 2개, 반려 1개 |
| 데일리 | 생성일 기준 7일간 하루 5문항 |
| 기록 | 출석 XP, 최초 학습 완료·전부 정답 보너스, 오답, 후속 안내, 모임 알림 |

GTO 예시는 팟 100·베팅 50의 단일 스트리트 0합 모형입니다. 계산식과 가정이 공개되어 있으며 실전 홀덤 솔버 결과를 흉내 낸 데이터가 아닙니다. 검수 기록은 테스트용으로 자동 생성되었음을 명시합니다. 실제 운영 출제 전에 별도 검수가 필요합니다.

## 로그인

로그인은 이메일로만 진행합니다. 기존 테스트 계정과 비밀번호는 그대로 사용합니다.

계정별 무작위 비밀번호는 저장소 밖 `~/donuts-test-data/<실행 폴더>/accounts.md`에만 저장합니다. 해당 폴더는 소유자만 접근하며 파일 권한은 `0600`입니다.

| 로그인 이메일 | 용도 |
|---|---|
| `demo_member@donuts-demo.invalid` | 기본 확인 계정. 복수 소속, 모임 신청, 오늘의 학습 |
| `demo_classlead@donuts-demo.invalid` | 클래스·회차·출석 및 두 번째 클럽 관리, 학습 만점 기록 |
| `demo_clublead@donuts-demo.invalid` | 첫 번째 클럽 소속 승인 및 본인이 만든 모임 운영 |
| `demo_waitlist@donuts-demo.invalid` | 대기열, 자리 확정·거절 |
| `demo_applicant@donuts-demo.invalid` | 클래스·클럽 승인 대기, 미소속 상태의 게스트 모임 |
| `demo_history@donuts-demo.invalid` | 출석·XP, 지난 모임, 학습 오답·통계 |

이메일은 수신함이 없는 `@donuts-demo.invalid`입니다. 테스트에 한해 Auth 관리 API로 인증 완료 상태를 부여하며 인증 메일을 보내지 않습니다. 별도 비밀번호 테이블이나 공통 고정 비밀번호는 사용하지 않습니다. 신규 관리자 계정은 만들지 않습니다.

관리자 기능은 기존 관리자 계정으로 확인합니다. 관리자에게 가짜 회원 프로필을 만들지 않으므로, 일반 회원의 학습 제출·참여 흐름은 테스트 회원으로 확인하세요.

## 권장 확인 순서

1. `/login`에서 `demo_member@donuts-demo.invalid`로 로그인해 `/class`, `/club`, `/home`, `/my`를 확인합니다.
2. `demo_classlead@donuts-demo.invalid`로 `/leader/class`에서 입문반의 진행 중 회차 출석을 저장·잠금·완료합니다. 완료한 1회차를 잠금 해제해 수정한 뒤 다시 잠그면 XP 정정 이력을 확인할 수 있습니다.
3. 향후 회차의 날짜를 개별 이동하거나 이후 회차까지 이동합니다. 종료반은 관리자에서 이력·정정 시나리오에 사용할 수 있습니다.
4. `demo_applicant@donuts-demo.invalid`의 소속 신청을 클래스장과 클럽장이 각각 승인합니다. 승인 전에는 정회원이어도 해당 클럽의 회원 전용 모임에 참여할 수 없습니다.
5. `demo_member@donuts-demo.invalid`로 신청 가능한 모임에 참여합니다. 만석 모임에서 자신의 확정 신청을 취소하면 다음 대기자에게 자리가 제안됩니다.
6. `demo_waitlist@donuts-demo.invalid`로 자리 확정 대기 모임에 들어가 제안을 확정하거나 거절합니다. 제안은 생성 후 12시간이 지나면 만료되므로 시나리오 상태는 이후 달라질 수 있습니다.
7. `demo_applicant@donuts-demo.invalid`의 게스트 모임 참여가 클럽 소속을 자동 생성하지 않는지 확인합니다.
8. `demo_member@donuts-demo.invalid` 또는 `demo_history@donuts-demo.invalid`의 MY에서 `지난 모임 보기`를 켭니다. 24시간이 지난 모임은 일반 모임 목록 대신 참가자의 이력에서 볼 수 있습니다.
9. 관리자 `/admin/successors`에서 자동 소속 실행 대기반을 미리보고 실행합니다. 등록 안내반은 이미 알림만 전송된 상태이며 별도 신청·승인이 필요합니다.
10. `demo_member@donuts-demo.invalid`로 `/learn`의 5문항을 제출합니다. `demo_history@donuts-demo.invalid`로 `/learn/review`와 MY의 오답·통계를 확인합니다. 최초 제출은 하루 한 번이며 테스트 데이터라고 제한을 해제하지 않습니다.
11. 관리자 `/admin/learning`에서 초안·반려·기존 문항의 개정 버전을 확인하고 직접 검수합니다. 이미 등록된 날짜의 출제 세트는 변경하지 않습니다.
12. `/notifications`에서 후속반과 모임 알림을 확인합니다. 이메일 수신 테스트는 포함하지 않습니다.

## 안전 경계

- 기존 관리자 계정·비밀번호, 일정 27개·시리즈, 가입 접수 상태를 변경하지 않습니다.
- 새 기능의 핵심 테이블이 비어 있을 때만 실행하며 기존 데이터를 덮어쓰거나 반복 생성하지 않습니다.
- 소속 신청·승인, 출석·XP, 모임 대기열, 후속 클래스, 학습 제출은 기존 원자적 DB 함수를 사용합니다.
- 테스트 계정의 XP만 생성합니다. 실제 가입 동의나 사람의 정식 문항 검수가 있었다고 표시하지 않습니다.
- 이번에 생성된 이메일 대기 작업은 취소 상태로 남깁니다. 실제 발송 API는 호출하지 않습니다.
- 이후 사용자가 테스트를 계속하거나 자동 만료 작업이 실행되면 추가 테스트 알림 큐가 생길 수 있습니다. Resend 실발송을 켜기 전에 테스트 데이터를 정리하세요.
- 실행별 `manifest.json`에 계정과 엔티티의 ID를, `applied.sql`에 데이터 생성 작업을 보관합니다. 테스트 후 제거할 때는 이 ID를 기준으로 다른 회원의 참여 이력이 생겼는지 확인해야 합니다.
- 오류나 네트워크 타임아웃이 나면 새 계정과 적용 SQL을 보존하고 중단합니다. 불확실한 상태에서 자동 삭제나 재실행을 하지 않습니다.
- 이 문서는 시나리오 안내이며 실제 브라우저 테스트를 모두 수행했다는 보고서가 아닙니다.

## 실행

기존 관리자 이메일과 대상 프로젝트를 명시해야 합니다. 운영 데이터가 존재하면 중단합니다.

```sh
node scripts/seed-demo-domains.mjs --apply --project PROJECT_REF --admin-email EXISTING_ADMIN_EMAIL
```
